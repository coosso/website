很多人用 Claude Code 的方式，还停留在"打开终端，问一个问题，复制答案"。这没有错，但离"进入工作流"还很远。

## 从单次问答到持续循环

真正有效的用法，是把它当作循环的一部分：

- **探索**：让它读代码、画结构、总结现状；
- **设计**：让它提出方案、列出权衡；
- **实现**：让它改代码、跑测试；
- **审查**：让它回头看自己改了什么，找出遗漏。

人在这个循环里的角色，从"写代码"变成了"做判断"。

## 上下文是资产

Claude Code 的强项之一，是对项目上下文的持续记忆。把约定写进 `CLAUDE.md`，把反复出现的任务沉淀成 skill，比每次重新解释一遍要高效得多。

好的上下文，是下一次对话的起点，而不是负担。

## 校验与边界

不要盲信输出。代码要跑、测试要过、结果要自己看。尤其对于不可逆的操作——发布、删除、对外提交——先确认再动手。

一句话总结：**把重复交给它，把判断留给自己。**
