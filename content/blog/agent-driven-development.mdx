过去一年，Agent 从"会写代码的补全工具"变成了"能独立完成任务的协作者"。它不再只是帮你补一行代码，而是可以接手一个 issue、探索一个陌生代码库、提交一个完整的改动。

## 从工具到协作者

工具是"你告诉它做什么，它做什么"。协作者是"你告诉它目标，它规划路径"。

这种转变带来的最大变化是：我们的注意力从**怎么实现**上移到**要实现什么**。提示词变成了规格说明书，审查（review）变成了新的核心技能。

## 边界在哪里

Agent 越强大，边界就越重要：

- **哪些操作可以自动执行，哪些必须人工确认**——比如对外发布、删除数据；
- **上下文如何管理**——Agent 的上下文就是它的工作记忆，也是它的局限；
- **谁来为结果负责**——最终的决定权必须留在人手里。

## 新的工作流

一个可行的 Agent 工作流大概是这样的：

1. 把任务描述清楚，包括背景、约束和验收标准；
2. 让 Agent 先探索、再规划、后执行；
3. 人负责审查结果，而不是盯着每一步；
4. 把反复出现的模式沉淀成可复用的 skill 或脚本。

工具会一直变，但"想清楚要什么"这件事，永远值得练习。
